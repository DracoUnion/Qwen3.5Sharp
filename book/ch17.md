# 第 17 章 这台引擎的边界，以及它还能走向哪

> 面向初学者：这是全书最后一章正章。我们不追求"显得很完美"，而是诚实交代"没做什么、有什么限制、未来从哪继续"。每小节给出对应的**真实代码**位置。

任何诚实的工程书，结尾都给读者一张"地图的空白处"。这一章回答三个问题：哪些是我们**刻意不实现**的（非目标）、哪些是**已知的取舍**（约束与雷区）、未来**该往哪投入**（路线图）。

## 17.1 明确的非目标：哪些能力刻意不实现

先看一张表，把"我们没做什么"一次说清：

| 能力 | 现状 | 对应的真实代码 |
|------|------|---------------|
| 视觉 / 多模态 | 不支持 | `ModelConfig.RopeDim` 是 1 维部分旋转；无 3D 位置 id、无 M-RoPE 分段 |
| 投机解码 / MTP | 不支持 | `Program.ArgMax` 仅贪心，无 draft 模型 |
| 分块 Gated-DeltaNet | 只做顺序递推 | `GatedDeltaNetOps.RecurrentGatedDeltaRule` 顺序递推 |
| 采样器多样性 | 仅贪心 argmax | `Program.ArgMax` 取 max |
| KV 量化 | 无 | `_cacheK/_cacheV` 是 f32 |

"分块 Gated-DeltaNet"最容易误认为功能缺失：顺序递推与分块**数学等价**（同一个 delta rule，分块只是把一批 token 的排布做得更有缓亲和），llama.cpp 的逐 token decode 也走顺序递推。所以"只做顺序递推"是"正确的实现 + 一条明确的内存优化路线"，真正会动的是 `GatedDeltaNetOps` 的调用形态与状态布局，不是数学。

为什么刻意不做视觉/多模态？这本书的射程是"证明文本推理的完整因果链"；M-RoPE 分段会大幅增加实现面积，而收益是另一个完整的故事。标进"非目标"，是为了让读者明确知道雷达边界，而不是以为雷达坏了。

## 17.2 已知限制：能跑，但别在这些边上踩雷

六条"知道就不踩雷"的约束，每条给"为什么是"与"怎么绕"。

### 1. 热路径依赖 AVX2+FMA

`MulMatQ2.QuantizeAndGemm`、`MulMatSTQ` 在无 AVX2 时抛 `PlatformNotSupportedException`（真实代码）：

```csharp
private static void RunQuantized(...)
{
    if (!Avx2.IsSupported)
        throw new PlatformNotSupportedException("Q2 panels require AVX2.");   // panel 优化无意义就明确拒绝
}
```

其余格式有标量回退（`DotScalar*` 兄弟，正确但慢）。无 AArch64/NEON 路径。

### 2. `token_embd` / 量化张量的 `nIn` 必须是 256 的倍数

`Qwen35Model.LoadWeights`（真实代码）：

```csharp
if (nIn % Qk.SuperBlock != 0)
    throw new NotSupportedException($"{name}: nIn={nIn} is not a multiple of 256");
```

模型发布方天然满足；极端特例需先 pad 或走 F32 fallback。

### 3. 只有 `nOut >= 8` 且 `nExpert == 1` 的 Q4_K/Q6_K/Q2_0C/STQ1_0 才重打包

`LoadWeights` 里 `if (nOut >= 8 && nExpert == 1) { ... }`——逐层决定 panel 或 GEMV（`MulMat*` 路由天然支持混合）。

### 4. STQ1_0 兼容标记有条件

`CanonicalTensorType` 需 raw type 42 + file_type 41 + 名含 `Stride16` 才规范化成 STQ1_0（第 3.6 节）。

### 5. 前缀缓存截断不影响线性层

`TruncateCache` 只回滚 KV；线性状态 `_linState`/`_linConv` 只增不缩——`ResetCache` 全清。约束对话形态（缓存只增、/reset 才清）。

### 6. `EnsureScratch` 用启发式估算

`Bump` 越界抛 `InsufficientMemoryException`（第 8.4 的真实代码）。按异常提示重算估算公式——"已知改进点"而非"未修复 bug"。

## 17.3 未来路线：从这本书出发，能走向哪里

按"低垂果实 → 工程中期 → 长远愿景"分三层，每层指向具体的源码位置。你不是从零探索，而是沿着已知路标往前走。

```mermaid

        A2["Gated-DeltaNet 就地归一化<br/>(GatedDeltaNetOps.cs)"]
        A3["向量化三 pass<br/>(DeltaStep)"]
        A4["prefill 插桩补全<br/>(Ticks*)"]
    end
    subgraph 第二层：工程中期
        B1["分块复现 chunk"]

    end
    subgraph 第三层：长远愿景
        C1["ARM64 / NEON 路径"]
        C2["CLI 采样丰富"]
        C3["投机解码 / MTP"]
    end
    A1 --> B1 --> C1
```

### 第一层：低垂果实（不动架构的优化）

1. **MoE 批处理**（`Qwen35Model.Moe.cs`）：同一专家多 token 的 GEMV 合并 panel GEMM；共享专家已用 GEMM。ROI 最高。
2. **Gated-DeltaNet 就地归一化**（`GatedDeltaNetOps.cs`）：L2 归一化免去每 token 的 `float[]` 分配。
3. **向量化三 pass**（`DeltaStep`）：以 `GatedDeltaNetOpsTests` 为不破门槛。
4. **prefill 插桩补全**（`Ticks*`）：让剖面覆盖 prefill 的 conv/recurrence。

### 第二层：工程中期（动内存布局的优化）

5. **分块复现（chunk）**：改 `RecurrentGatedDeltaRule` 调用形态，数学不变。
6. **KV 量化（f16/i8）**：给 `_cacheK/_cacheV` 加量化/反量化内核，松绑 decode 带宽。
7. **更多量化类型读入**：Q3_K、TQ/TQ2、BF16；Q5_K/IQ4_XS/STQ1_0 的 prefill panel GEMM。
8. **端到端测试与基准**：加公开小 GGUF 做生成冒烟 + tok/s 基准。

### 第三层：长远愿景（把引擎推向更多人）

9. **ARM64 / NEON 路径**：为 AArch64 .NET 提供 NEON/SVE 内核回退。
10. **CLI 采样丰富**：top-k/top-p/温度、`--seed`、KV 状态导出。
11. **投机解码 / MTP**：把第 2 章"非目标"的大件拉回来——那又是一本书的深度。

### 一个收尾的呼告

还记得第 1 章我们开的工吗？四个回合：文件回合（`GgufFile`）、计算回合（`VecDotQ4K`/`GemmQ4K`/`CpuThreadPool`）、模型回合（`ModelConfig`/`Qwen35Model`）、用户回合（`BpeTokenizer`/`ChatTemplate`/`Program`）。现在，四个回合都走完了：引擎在终端说话，测试锁住正确性，剖析看见时间，边界画好地图。

但"从零自制"从来不是终点，而是**让读者有能力继续往里挖**的起点。这本书给你的，不是一份成品源码的复印件，而是一条"我亲手把一坨权重字节变成一句人话"的完整路径，和一路上所有值得停下来思考的岔路口。

> **全书写到这里，最后一句话送给读者**：自制引擎最重要的产出，不是那个能对话的程序，而是在建造它的过程中，你亲手建立起来的、关于"计算是如何真正发生"的直觉力。愿这本书成为你直觉的垫脚石。
