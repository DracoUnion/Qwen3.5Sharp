# 第 12 章 稀疏 FFN：只算被选中的专家

> 面向初学者：本章实现"稀疏专家混合"（MoE）——把 FFN 换成一群"专家"，每个词只叫醒其中几个。用"点菜"的比喻讲清楚，每小节贴 `src/Qwen35Sharp.Model/Qwen35Model.Moe.cs` 的**真实源码**。

第 11 章填完了"四层里三层的线性注意力"。模型骨架还剩最后一块个性化部件：FFN。dense 的 FFN 第 9 章已经会算；本章补上 `qwen35moe` 变体——**稀疏 MoE**。核心命题：与其让所有 token 走同一个巨大 FFN，不如准备几百个"专家"，每个 token 只让 top-k 个专家干活。

## 12.1 MoE 的数学与一次计算的全流程

先看 MoE 的"规格说明书"——`Qwen35Model.Moe.cs` 的文件头注释（大白话版）：

```
MoE FFN (sparse), arch "qwen35moe"
  router_logits = x @ ffn_gate_inp^T                # 一个"路由器"给每个专家打分
  probs = softmax(router_logits)
  top-k indices/weights -> normalize weights to sum 1   # 选前 k 名专家，权重归一化为 1
  out   = Σ_k expert_weight * Expert_k(silu(gate_k(x)) * up_k(x))   # 专家们干活，加权求和
  shared = sigmoid(x @ ffn_gate_inp_shexp^T) * SharedFFN(x)          # 共享专家（人人都有份）
  out  += shared
```

打个比方：这就像"点菜"。全注意力 FFN 相当于"每天都把整个后厨 256 个厨师都用上"；MoE 是"一个点菜的管家（路由器）先看这道菜适合谁，只叫 8 个厨师（top-k 专家）来做"，最后大家一起拼成一道菜。

`PrefillSparseMoe` 的四步（真实代码节选，带注释）：

```csharp
private void PrefillSparseMoe(float* input, float* output, int layer, int seq)
{
    int hidden = Config.HiddenSize;
    int nExperts = Config.NumExperts;          // 专家总数（如 256）
    int nUsed = Config.NumExpertsPerTok;       // 每个 token 用几个（top-k，如 8）
    int ffn = Config.MoeFfnSize;

    // ① 路由器打分：[rows, nExperts]
    float* routerLogits = (float*)Bump((nuint)((long)rows * nExperts * sizeof(float)));
    Linear(_weights[$"blk.{layer}.ffn_gate_inp.weight"], input, routerLogits,
           hidden, nExperts, rows);

    // ② softmax + top-k 选专家
    int* indices = (int*)Bump((nuint)((long)rows * nUsed * sizeof(int)));
    float* weights = (float*)Bump((nuint)((long)rows * nUsed * sizeof(float)));
    TopKSoftmax(routerLogits, rows, nExperts, nUsed, indices, weights);

    // ③ 对每个"token × 选中专家"，算 gate/up → SiLU → down → 加权累加
    for (int r = 0; r < rows; r++)
    {
        float* x = input + (long)r * hidden;
        for (int k = 0; k < nUsed; k++)
        {
            int exp = indices[r * nUsed + k];      // 第 k 个被选中的专家
            float w = weights[r * nUsed + k];      // 它的权重
            float* gate = (float*)Bump((nuint)(ffn * sizeof(float)));
            float* up = (float*)Bump((nuint)(ffn * sizeof(float)));
            ExpertGateUp(x, layer, exp, gate, up, hidden, ffn);   // 两个 GEMV
            Ops.SiLUMul(gate, up, ffn, pool: null);               // silu(gate)·up
            float* down = (float*)Bump((nuint)(hidden * sizeof(float)));
            ExpertDown(gate, layer, exp, down, ffn, hidden);      // 向下投影
            float* o = output + (long)r * hidden;
            for (int d = 0; d < hidden; d++) o[d] += w * down[d]; // output += w·down
        }
    }
    // ④ 共享专家（若有）：人人有份的基础菜
    if (_weights.ContainsKey($"blk.{layer}.ffn_gate_shexp.weight")) { /* 见 12.3 */ }
}
```

MoE 的收益一句话：**"token × 巨大 FFN" → "token × top-k 小专家 + 便宜路由器"**。Qwen3.5 MoE 有 256 专家、每 token 激活 8 个——算力只有全员都算的 8/256 ≈ 1/32。

两个正确性要点（易错）：

- **top-k 重归一化发生在 softmax 之后**（`Σw=1`）。
- **共享专家与主 MoE 的相加顺序**与参考实现一致。

## 12.2 3D 专家张量：一个张量装下全员

`ffn_gate_exps`/`up_exps` 形状 `[hidden, moeFfn, numExperts]`，`ffn_down_exps` 是 `[moeFfn, hidden, numExperts]`——**专家在第三维**。`Weight` 的两个字段是为它准备的（`Qwen35Model.cs`）：

```csharp
public int NExpert;
public long ExpertStride; // byte offset between experts for 3D tensors
```

`ExpertBase` 定位第 exp 个专家的切片（真实代码，`Qwen35Model.Moe.cs`）：

```csharp
/// <summary>Base pointer of one expert slice, offset by type-specific pointer.</summary>
private static byte* ExpertBase(Weight w, int exp)
{
    byte* p = w.Type switch
    {
        GgmlTensorType.IQ4_XS => (byte*)w.Q4xs,
        GgmlTensorType.Q5_K   => (byte*)w.Q5,
        GgmlTensorType.Q4_K   => (byte*)w.Q4,
        _ => throw new NotSupportedException($"{w.Type} expert weight"),
    };
    return p + exp * w.ExpertStride;   // 第 exp 个专家的字节偏移
}
```

**为什么记录字节步长而非"按 NOut 线性估计"**？3D 张量的专家沿第三维切片，切片间距 = "一个专家完整一块" = `nOut·nb·blockBytes`。**为什么加载期不重打包成 panel**？MoE 在 decode 只做逐专家 GEMV、每次只激活 top-k——panel 的"8 列一起喂"收益被稀释（`LoadWeights` 里 `nExpert==1` 才重打包）。

## 12.3 路由：TopKSoftmax 与共享专家门控

`TopKSoftmax`（真实代码）——softmax 后贪心 top-k，然后是重归一化：

```csharp
/// <summary>softmax(x) then pick the top-k entries per row; renormalize the top-k
/// weights to sum to 1. Writes indices (descending by weight) and weights.</summary>
private void TopKSoftmax(float* logits, int rows, int nExperts, int nUsed,
    int* indices, float* weights)
{
    for (int r = 0; r < rows; r++)
    {
        float* row = logits + (long)r * nExperts;
        // ① softmax：先减 max 保证数值稳定
        float max = row[0];
        for (int i = 1; i < nExperts; i++) if (row[i] > max) max = row[i];
        float sum = 0;
        for (int i = 0; i < nExperts; i++) { row[i] = MathF.Exp(row[i] - max); sum += row[i]; }
        float inv = 1f / sum;
        for (int i = 0; i < nExperts; i++) row[i] *= inv;

        // ② 贪心选 top-k：nUsed ≤ 8、nExperts ~256，线性扫描就够了
        for (int k = 0; k < nUsed; k++)
        {
            int best = -1; float bestV = -1f;
            for (int i = 0; i < nExperts; i++)
                if (row[i] > bestV) { bestV = row[i]; best = i; }
            idx[k] = best; wgt[k] = bestV;
            row[best] = -1f;                // 置 -1 排除，下一轮找次大的
        }
        // ③ 重归一化选中的权重
        float wsum = 0;
        for (int k = 0; k < nUsed; k++) wsum += wgt[k];
        float winv = wsum > 0 ? 1f / wsum : 0f;
        for (int k = 0; k < nUsed; k++) wgt[k] *= winv;
    }
}
```

**为什么"重归一化在 softmax 之后"**？因为 softmax 已编码专家间的相对权重；top-k 之后再 re-scale，比例不变、总和 1。若先 top-k 再 softmax，数值与参考不完全一致。

共享专家的门控（`PrefillSparseMoe` 第 4 步，真实代码）：

```csharp
if (_weights.ContainsKey($"blk.{layer}.ffn_gate_shexp.weight"))
{
    // shared = sigmoid(x @ ffn_gate_inp_shexp^T) * SharedFFN(x)
    float* sharedGateLogit = (float*)Bump((nuint)(rows * sizeof(float)));
    F32Gemm(_weights[$"blk.{layer}.ffn_gate_inp_shexp.weight"].F32, input,
            sharedGateLogit, hidden, 1, rows);                     // 每行一个标量 logit

    float* sharedGate = Bump(rows * MoeSharedFfnSize);
    float* sharedUp = Bump(rows * MoeSharedFfnSize);
    Linear(_weights[$"blk.{layer}.ffn_gate_shexp.weight"], input, sharedGate, hidden, Config.MoeSharedFfnSize, rows);
    Linear(_weights[$"blk.{layer}.ffn_up_shexp.weight"], input, sharedUp, hidden, Config.MoeSharedFfnSize, rows);
    Ops.SiLUMul(sharedGate, sharedUp, rows * MoeSharedFfnSize, _pool);
    float* sharedOut = Bump(rows * hidden);
    Linear(_weights[$"blk.{layer}.ffn_down_shexp.weight"], sharedGate, sharedOut, Config.MoeSharedFfnSize, hidden, rows);

    for (int r = 0; r < rows; r++)
    {
        float sg = 1f / (1f + MathF.Exp(-sharedGateLogit[r]));   // sigmoid 门控
        for (int d = 0; d < hidden; d++) o[d] += sg * s[d];
    }
}
```

## 12.4 逐专家 GEMV 与性能取舍

`ExpertGateUp`/`ExpertDown`（`Qwen35Model.Moe.cs`）用 `ExpertBase` 拿切片再走 GEMV：

```csharp
/// <summary>gate/up = x @ Expert_k(gate|up)^T for one expert. The weight is a 3D
/// tensor with nIn innermost; the expert's slice is at a byte stride.</summary>
private void ExpertGateUp(float* x, int layer, int exp, float* gate, float* up,
    int hidden, int ffn)
{
    byte* gBase = ExpertBase(wg, exp);
    byte* uBase = ExpertBase(wu, exp);
    switch (wg.Type)
    {
        case GgmlTensorType.IQ4_XS:
            IQ4XS.Gemv((BlockIQ4XS*)gBase, x, gate, hidden, ffn, _pool);   // 专家 gate
            IQ4XS.Gemv((BlockIQ4XS*)uBase, x, up, hidden, ffn, _pool);     // 专家 up
            break;
        case GgmlTensorType.Q5_K:   /* Q5K.Gemv ×2 */  break;
        case GgmlTensorType.Q4_K:   /* MulMatQ4K.Gemv ×2 */ break;
    }
}
```

两个诚实的性能注脚：**每次 GEMV 独立量化**（同一行 x 被 top-k 个专家各量化一次，优化方向是 `GemvPrequant` 路线）；**逐 token 逐专家串行**（改用"同一专家多个 token 合并 panel GEMM"是明确热点）。

**`ExpertWeightsScale` 待办**：`Config.ExpertWeightsScale` 已从 GGUF 读入但未应用到专家输出（若需乘法缩放，应在 `output[r] += w·down` 处乘它）——诚实清单的一部分。
