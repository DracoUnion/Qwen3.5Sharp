# 第 6 章 一次算一批：面板重打包与 panel GEMM

> 代码锚点贯穿正文。核心文件：`src/Qwen35Sharp.Kernels/BlockLayout.cs`、`RepackQ4K.cs`、`RepackQ6K.cs`、`RepackQ2.cs`、`RepackSTQ.cs`、`QuantizeQ8Kx4.cs`、`GemmQ4K.Avx2.cs`、`GemmQ6K.cs`、`Q2Panel.cs`、`STQPanel.cs`、`MulMatPanel.cs`、`MulMatQ2.cs`、`MulMatQ4K.cs`。

第 5 章的 decode 路径有个软肋：一行一行算。而 prefill 要一次消化几十上百个 token。这一章回答：**怎么把"一次一个 token"变成"一次一整批"？** 答案是一个被推到极致的思路：

> 把"位手术"从热循环搬走，在加载期把权重重排成"面板"并预解码尺度；热循环里只剩乘和加。

这就是"面板重打包 + panel GEMM"。

## 6.1 prefill 的痛点：为什么 GEMV 撑不起长提示词

一次 prefill 处理 `S` 个 token 的激活（`[S, nIn]`），与权重（`[nOut, nIn]`）做 `Y = X·Wᵀ`。若用第 5 章的 GEMV，就是 `S` 次独立的"一行输入 × 全部权重行"：每次扫全量权重、SIMD 只吃在 `nIn` 方向、位手术重复 S 次。

于是答案：**在输出方向的 8 个列上并行——一次处理 4 个 token、8 个输出列**。这个"4×8"的块度，是 llama.cpp 生态演化出的自然选择，也是整套 panel 的形态。调度命令在 `Qwen35Model` 层由 `Linear` 的 `tokens==1` 判分支（第 8 章 `Qwen35Model.Decode.cs`）：

```csharp
private void Linear(Weight w, float* input, float* output, int nIn, int nOut, int tokens)
{
    switch (w.Type)
    {
        case GgmlTensorType.Q4_K:
            MulMatQ4K.Gemm(w.Packed, w.Q4, input, output, nIn, nOut, tokens, _pool, _gemmScratch, w.Meta);
            break;
        case GgmlTensorType.Q2_0C:
            MulMatQ2.Gemm(w.Packed2, w.Q2, input, output, nIn, nOut, tokens, _pool, _gemmScratch);
            break;
        case GgmlTensorType.STQ1_0:
            MulMatSTQ.Gemm(w.PackedSTQ, w.STQ, input, output, nIn, nOut, tokens, _pool, _gemmScratch);
            break;
        case GgmlTensorType.Q6_K:
            Q6K.Gemm(w.Q6, input, output, nIn, nOut, tokens, _pool, _gemmScratch);
            break;
        // ...
    }
}
```

而 `MulMatQ4K.Gemm` 内的三件杂务（补 4、补 8、scratch）在 `Qwen35Sharp.Kernels/MulMatQ4K.cs`：

```csharp
public static void Gemm(BlockQ4Kx8* packed, BlockQ4K* rows, float* input, float* output,
    int nIn, int nOut, int tokens, CpuThreadPool? pool = null, ScratchArena? scratch = null,
    BlockQ4Kx8Meta* meta = null)
{
    if (tokens == 1) { Gemv(rows, input, output, nIn, nOut, pool, scratch); return; }  // ← 路由

    int paddedTokens = (tokens + 3) & ~3;   // 补到 4 的倍数
    int packedCols = nOut & ~7;             // 8 的倍数主体
    // ... 对齐/补零/回拷、scratch 分配、QuantizeAndGemmPrequant、尾部 Dot 补算 ...
}
```

## 6.2 重新排布世界的这一刻：panel 到底是什么

Panel（面板）是加载期的一种**内存布局变换**：把"8 个输出行"的权重按列交织重排成一个宽块。最典型的 Q4_K 面板 `BlockQ4Kx8`（`BlockLayout.cs`，1152 字节）：

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 1)]
public unsafe struct BlockQ4Kx8
{
    public fixed ushort D[8];
    public fixed ushort Dmin[8];
    public fixed byte Scales[96];   // 8 列 × 12 字节 scales 重排
    public fixed byte Qs[1024];     // 8 列 × 256 值，列交织：chunk j(64B) = 列0..7 × K值4j..4j+3
}
```

**预解码 meta** `BlockQ4Kx8Meta`（448 字节）是 Q4_K 最狠的一手：

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 1)]
public unsafe struct BlockQ4Kx8Meta
{
    public fixed float D[8];
    public fixed float Dmin[8];
    public fixed short Scales[4 * 48];   // vphaddw 顺序 + mins 交错，加载期算好
}
```

落地这些重排的是四个 `Repack*` 类。`RepackQ4K`（`src/Qwen35Sharp.Kernels/RepackQ4K.cs`）的 `Rows` 与 `BuildMeta`：

```csharp
public static void Rows(BlockQ4K* src, BlockQ4Kx8* dst, int nIn, int nOut)
{
    int nb = nIn / Qk.SuperBlock;
    int groups = nOut / 8;
    BlockQ4K* tmp = stackalloc BlockQ4K[8];
    for (int g = 0; g < groups; g++)
        for (int b = 0; b < nb; b++)
        {
            for (int r = 0; r < 8; r++) tmp[r] = src[(g * 8 + r) * nb + b];
            MakeBlockX8(tmp, &dst[g * nb + b]);
        }
}
```

```csharp
public static void BuildMeta(BlockQ4K* src, BlockQ4Kx8Meta* dst, int nIn, int nOut)
{
    int nb = nIn / Qk.SuperBlock;
    // vphaddw(cols0123, cols4567) lane order.
    ReadOnlySpan<byte> order = [0, 0, 1, 1, 4, 4, 5, 5, 2, 2, 3, 3, 6, 6, 7, 7];
    for (int g = 0; g < nOut / 8; g++)
        for (int b = 0; b < nb; b++)
        {
            BlockQ4Kx8Meta* meta = dst + g * nb + b;
            for (int j = 0; j < 8; j++)
            {
                BlockQ4K* block = src + (g * 8 + j) * nb + b;
                meta->D[j] = HalfBits.ToSingle(block->D);
                meta->Dmin[j] = HalfBits.ToSingle(block->Dmin);
            }
            for (int pair = 0; pair < 4; pair++)
            {
                short* lo = meta->Scales + pair * 48;
                short* hi = lo + 16; short* mins = lo + 32;
                for (int half = 0; half < 2; half++)
                {
                    for (int j = 0; j < 8; j++)
                        ScaleMin(..., out sc[j], out mn[j]);
                    short* target = half == 0 ? lo : hi;
                    for (int i = 0; i < 16; i++) target[i] = sc[order[i]];
                    for (int j = 0; j < 8; j++) mins[j * 2 + half] = mn[j];
                }
            }
        }
}
```

`RepackQ6K`（展开成 u8 0..63 + ScalePairs）、`RepackQ2`（拆 2-bit 跨列/plane 重排）、`RepackSTQ`（码本解码 → 0/1/2 panel）走同一条路：

```csharp
// RepackQ6K：把 6-bit 展开成 u8 0..63，-32 修正留给 GEMM
public static void Expand(BlockQ6K* block, byte* values)
{
    byte* ql = block->Ql; byte* qh = block->Qh;
    for (int n = 0; n < Qk.SuperBlock; n += 128)
        for (int l = 0; l < 32; l++)
        {
            values[n + l]        = (byte)((ql[l] & 0xF) | ((qh[l] & 3) << 4));
            values[n + l + 32]   = (byte)((ql[l + 32] & 0xF) | (((qh[l] >> 2) & 3) << 4));
            values[n + l + 64]   = (byte)((ql[l] >> 4) | (((qh[l] >> 4) & 3) << 4));
            values[n + l + 96]   = (byte)((ql[l + 32] >> 4) | (((qh[l] >> 6) & 3) << 4));
        }
}
```

连**激活**也重排成 4 行的面板 `BlockQ8Kx4`（6.3），对称成"4 token 一次量化、一次喂 GEMM"。

## 6.3 Q8_Kx4：把激活也排成 4 行的面板

`BlockQ8Kx4`（1168 字节）把 4 个 Q8_K 块（= 4 token 各 256 值）交织：

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 1)]
public unsafe struct BlockQ8Kx4
{
    public fixed float D[4];
    public fixed sbyte Qs[Qk.SuperBlock * 4];   // 每 32 字节 = 4 行 × 8 值
    public fixed short Bsums[Qk.SuperBlock / 4]; // 重排成 ((t>>2)<<4)+(t&3) 顺序
}
```

`QuantizeQ8Kx4.Quantize4x8` 一次并行量化 4 个 token；标志性的 `Quantize4x8Avx2`（`QuantizeQ8Kx4.cs`）用 `PermuteVar8x32` 完成行内重排：

```csharp
public static void Quantize4x8Avx2(float* x, BlockQ8Kx4* y, int k)
{
    int nb = k / Qk.SuperBlock;
    Vector256<int> perm = Vector256.Create(0, 4, 1, 5, 2, 6, 3, 7);
    for (int i = 0; i < nb; i++)
    {
        float is0 = Q8K.ScaleBlock(x + 0 * k + i * Qk.SuperBlock, out float d0);
        // ... is1/is2/is3 ...
        y[i].D[0] = d0; // ... D[1..3] ...
        for (int j = 0; j < 32; j++)
        {
            Vector256<int> i0 = Quant8(x + 0 * k + i * Qk.SuperBlock + j * 8, isv0, qmin, qmax);
            // ... i1/i2/i3 ...
            Vector256<short> p01 = Avx2.PackSignedSaturate(i0, i1);
            Vector256<short> p23 = Avx2.PackSignedSaturate(i2, i3);
            Vector256<sbyte> packed = Avx2.PackSignedSaturate(p01, p23);
            packed = Avx2.PermuteVar8x32(packed.AsInt32(), perm).AsSByte();
            Avx.Store((byte*)(y[i].Qs + 32 * j), packed.AsByte());
        }
        FillBsums(y[i].Qs, y[i].Bsums);
    }
}
```

融合版本 `Quantize4x8Silu`（FFN 的 `ffn_down = W_d·silu(gate)⊙up` 直接受益）把 silu·up 算进量化循环：

```csharp
public static void Quantize4x8Silu(float* gate, float* up, BlockQ8Kx4* y, int k)
{
    float* tmp = stackalloc float[4 * Qk.SuperBlock];
    int nb = k / Qk.SuperBlock;
    for (int i = 0; i < nb; i++)
    {
        for (int row = 0; row < 4; row++)
            SiluMulBlock(gate + row * k + i * Qk.SuperBlock,
                         up + row * k + i * Qk.SuperBlock, tmp + row * Qk.SuperBlock);
        Quantize4x8(tmp, y + i, Qk.SuperBlock);
    }
}
```

## 6.4 4×8 GEMM：热循环只做乘加

`src/Qwen35Sharp.Kernels/GemmQ4K.Avx2.cs` 的 `GemmAvx2`——**列分块**与**无 shuffle 端口**的结构：

```csharp
public static int ColTileBytes = 128 * 1024;   // 列方向 L2 分块的字节数

public static void GemmAvx2(int n, float* dst, int ldc, BlockQ4Kx8* weights,
    BlockQ8Kx4* activations, int rows, int cols, BlockQ4Kx8Meta* meta)
{
    int nb = n / Qk.SuperBlock;
    int tileGroups = Math.Max(1, ColTileBytes / (nb * Qk.Q4Kx8Size));
    int groups = cols / 8;
    for (int g0 = 0; g0 < groups; g0 += tileGroups)
        GemmAvx2Tile(n, dst + g0 * 8, ldc, weights + g0 * nb, activations,
                     rows, Math.Min(tileGroups, groups - g0) * 8, meta + g0 * nb);
}
```

内部 `GemmAvx2Tile` 的每个 panel 节，对 4 个激活行（`r`）分别 `vpbroadcastq`（纯加载）对原始列交织 nibble 做 `vpmaddubsw`，每 8 个乘加只配 8 adds/2 ands/6 loads——无 shuffle 端口竞争。scales 从 meta 预解码直接 load。列序 `[0 1 4 5 2 3 6 7]` 在存储时用一次 `PermuteVar8x32` 修正。

`GemmQ6K`（`GemmQ6K.cs`）的 `−32` 修正——把 `Σ(sc·(q−32)·a)` 多出项 `−32·Σ(sc_i·bsum_i)` 提出、每 super-block 一次 `ShiftLeftLogical(c, 5)` 折叠：

```csharp
j0 = Avx2.Subtract(j0, Avx2.ShiftLeftLogical(c0, 5));   // ×32 减，一次搞定
```

`Q2Panel`/`STQPanel`（`Q2Panel.cs`/`STQPanel.cs`）是"一条 broadcast 喂多列"的同类，列序同样在存储前 `PermuteVar8x32(acc, ColumnOrder)` 修复：

```csharp
private static Vector256<int> ColumnOrder => Vector256.Create(0, 1, 4, 5, 2, 3, 6, 7);
// Gemv 用：dot 序列在输出前统一修正
Avx.Store(dst, Avx2.PermuteVar8x32(acc, ColumnOrder));
```

## 6.5 一石二鸟：共享量化与三连乘

`src/Qwen35Sharp.Kernels/MulMatPanel.cs` 把量化与 GEMM 合成一个协调动作：

```csharp
public unsafe struct PanelWeight
{
    public BlockQ4Kx8* Q4;
    public BlockQ4Kx8Meta* Meta;
    public BlockQ6Kx8* Q6;
    public float* Dst;
    public int NOut;
    public readonly bool IsEmpty => NOut == 0;
    public static PanelWeight ForQ4(...) => new() { Q4 = packed, Meta = meta, Dst = dst, NOut = nOut };
    public static PanelWeight ForQ6(...) => new() { Q6 = packed, Dst = dst, NOut = nOut };
}

public static void QuantizeAndGemm(float* input, BlockQ8Kx4* q8, int nIn, int tokens,
    CpuThreadPool? pool, PanelWeight w0, PanelWeight w1 = default, PanelWeight w2 = default)
{
    int nb = nIn / Qk.SuperBlock;
    int quantGroups = tokens / 4;
    pool?.For(Math.Max(quantGroups, w0.NOut / 8), (worker, workers) =>
    {
        int g0 = quantGroups * worker / workers, g1 = quantGroups * (worker + 1) / workers;
        for (int g = g0; g < g1; g++)
            QuantizeQ8Kx4.Quantize4x8(input + g * 4 * nIn, q8 + g * nb, nIn);   // 先量化
        pool.Barrier();                                                          // → 自旋 barrier
        GemmRange(w0, q8, nIn, tokens, worker, workers, nb);                     // 再连续 GEMM
        GemmRange(w1, q8, nIn, tokens, worker, workers, nb);
        GemmRange(w2, q8, nIn, tokens, worker, workers, nb);
    });
}
```

`SiluQuantizeAndGemm` 是 ffn_down 的融合版（quantize silu(gate)·up 进同一条线）。Q2 的对应物在 `MulMatQ2.QuantizeAndGemm`/`SiluQuantizeAndGemm`（第 12 章 MoE 也走它）。

## 6.6 调度路由：tokens==1 走 GEMV，否则走 GEMM

`MulMatQ4K.Gemm` 统一入口（6.1 已给），三个被低估的杂务：

1. **`PackedGroups(nOut) = nOut / 8`** 切面板节；`nOut%8` 尾部用逐行 `VecDotQ4K.Dot` 补算。
2. **token 数不是 4 的倍数**：`paddedTokens = (tokens+3)&~3` 补零到 4、`Buffer.MemoryCopy` 回拷。
3. **scratch 分配临时缓冲**：`scratch.A/B/C/D` 从 `ScratchArena` 拿，避免 new。

主线（`QuantizeAndGemmPrequant`）是 llama.cpp `mul_mat` 的精确移植——一个并行区段：量化组 → `pool.Barrier()` → GEMM 组。`GemmPrequant` 接受**已量好**的 Q8 面板（第 9 章 q/k/v 复用通道）。

> **一句话总结这一章**：prefill 慢的根源是逐行 GEMV 的重复解码与访存；解法是把权重重排成 8 列面板（`RepackQ4K.Rows`/`BuildMeta`、`RepackQ6K`/`RepackQ2`/`RepackSTQ`）、激活排成 4 行面板（`QuantizeQ8Kx4.Quantize4x8`/`Quantize4x8Silu`），热循环退化为纯乘加（`GemmQ4K.GemmAvx2`、`GemmQ6K`、`Q2Panel`/`STQPanel`）；`MulMatPanel.QuantizeAndGemm` 实现共享量化 + 三连乘。但这一切跑在**多少线程**、什么**内存布局**上？——第 7 章，线程池、CPU 拓扑与内存竞技场。
