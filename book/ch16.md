# 第 16 章 性能剖析：看见时间都去哪了

> 面向初学者：本章讲"性能优化第一步不是改代码，而是先看清时间花在哪"。你会学到 `Ticks*` 计数器、`Q35_TRACE`/`Q35_DIAG` 两个调试开关，以及贯穿全书的"性能设计六板斧"。每小节贴 `src/Qwen35Sharp.Model/Qwen35Model.cs` 的**真实源码**。

"算得对"之后，"算得快"是下一座山。性能优化的第一步永远是——**看见**。谁在慢？哪个算子吃最多时间？这一章把项目的剖析手段、诊断开关与已知瓶颈原样整理，教读者"先定位，再优化"。

这一章的走法：我们**首先**看内建剖析计数器——算子级耗时的秒表（16.1 节）；**其次**用两个调试开关 `Q35_TRACE`/`Q35_DIAG` 当手术探针，定位"哪里错了"（16.2 节）；**接着**全景回顾性能设计的六板斧（16.3 节）；**最后**把已知瓶颈与优化路线如实摆出来（16.4 节）。

## 16.1 内建剖析计数器：算子级耗时的秒表

`src/Qwen35Sharp.Model/Qwen35Model.cs` 的静态计数器（真实代码，带注释）：

```csharp
// 要开启剖析就把这个静态开关设为 true；跑几轮后 ResetProfile() 清零再测。
public static bool ProfileEnabled;
public static long TicksQ4, TicksQ2, TicksSTQ, TicksQ6;      // 各类型权重 GEMM/GEMV
public static long TicksAttnScore, TicksSoftmax, TicksAttnCombine;  // 注意力三段式
public static long TicksRms, TicksRope, TicksSilu, TicksEmbed;      // 逐点算子
public static long TicksDelta, TicksConv;                           // Gated-DeltaNet 递推与卷积

public static void ResetProfile()
{
    TicksQ4 = 0; TicksQ2 = 0; TicksSTQ = 0; TicksQ6 = 0;
    TicksAttnScore = 0; TicksSoftmax = 0; TicksAttnCombine = 0;
    TicksRms = 0; TicksRope = 0; TicksSilu = 0; TicksEmbed = 0;
    TicksDelta = 0; TicksConv = 0;
}
```

用法：`ProfileEnabled = true` 后，各算子用 `Stopwatch.GetTimestamp()` 包裹（decode 路径），例如 `Ops.NeoXRoPE` 调用处（`Qwen35Model.Decode.cs`）：

```csharp
long tRope = ProfileEnabled ? Stopwatch.GetTimestamp() : 0;      // 记录开始时刻
Ops.NeoXRoPE(q, seq, heads, dim, Config.RopeDim, start, Config.RopeBase, pool: null);
Ops.NeoXRoPE(k, seq, kvHeads, dim, Config.RopeDim, start, Config.RopeBase, pool: null);
if (ProfileEnabled)
    TicksRope += Stopwatch.GetTimestamp() - tRope;               // 累加耗时差
```

跑完几轮，把 `Ticks*` 除以 `Stopwatch.Frequency`（每秒有多少个 tick），就得到"占最大时间的算子分布"——**算子级剖面**，直接告诉你下一刀砍哪里。

```mermaid
graph LR
    A["跑几轮推理<br/>(ProfileEnabled=true)"] --> B["Ticks* 计数累加"]
    B --> C["除以 Frequency<br/>得到每个算子的耗时"]
    C --> D["找出最大的 Ticks*<br/>→ 那是优化目标"]
```

三个注脚：`Ticks*` 是 `static long`（剖析是诊断期的事，不该引入对象状态）；**部分计数器只在 decode 路径累积**（`TicksRope`/`TicksDelta`），prefill 未全部插桩；`ResetProfile` 清零是跑多轮前必做的，否则旧轮累积会污染"本轮分布"。

## 16.2 追踪与诊断：Q35_TRACE 与 Q35_DIAG

两个"手术探针"环境变量，专门定位"哪里错了"。

**Q35_TRACE=1**：每层每子步骤进入/完成留痕（`Qwen35Model.Prefill.cs` 的 `PrefillBlock` 里）：

```csharp
private void PrefillBlock(float* hidden, int layer, int seq, int start)
{
    bool trace = Environment.GetEnvironmentVariable("Q35_TRACE") == "1";
    void T(string s) { if (trace) Console.Error.WriteLine($"[PB L{layer}] {s}"); }
    Rms($"blk.{layer}.attn_norm.weight", hidden, n1, seq, hiddenSize);
    T("attn_norm ok");                     // 每一步都留一行痕
    if (Config.IsRecurrent[layer]) PrefillLinearAttn(n1, attn, layer, seq, start);
    else                          PrefillAttention(n1, attn, layer, seq, start);
    T("token-mixer ok");
    // ... "residual1 ok" / "gateup ok" / "silu ok" / "ffn_down ok" / "residual2 ok"
}
```

**Q35_DIAG=1**：每 3 层打印最后一 token 隐藏态 RMS 范数（`Forward` 里的真实代码）：

```csharp
if (Environment.GetEnvironmentVariable("Q35_DIAG") == "1" && layer % 3 == 2)
{
    float n2 = 0; float* lastTok = h + (long)(seq - 1) * hidden;
    for (int i = 0; i < hidden; i++) n2 += lastTok[i] * lastTok[i];
    Console.Error.WriteLine($"[diag] prefill after L{layer} ('{(Config.IsRecurrent[layer] ? "linear" : "full")}'): |h_last|={MathF.Sqrt(n2 / hidden):F3}");
}
```

专治**数值发散**：某处（如 Gated-DeltaNet 递推）指数爆炸时 `|h|` 突然飞飙，`Q35_DIAG` 直接打出"哪层开始炸"。

**一个诊断实例的工作流**（值得掌握的惯例）：

```
症状：输出乱码、重复 token
1. Q35_DIAG=1 跑一次短输入 → 看 |h| 从哪层偏离
2. Q35_TRACE=1 同输入 → 确认哪些子步骤被触发
3. 对可疑区设断点/加临时对拍 → 定位函数
4. 修 → 重跑 Q35_DIAG → |h| 恢复正常
```

## 16.3 性能设计的全景回顾：六板斧

全书散落的性能决策攒成一套体系——"性能设计六板斧"，每条回指真实代码：

| # | 板斧 | 真实代码 | 一句话 |
|---|------|---------|--------|
| 1 | **加载期重打包** | `RepackQ4K.Rows`/`BuildMeta`、`RepackQ6K`/`RepackQ2`/`RepackSTQ` | 位手术搬加载期，热循环只做乘加 |
| 2 | **decode/prefill 分流** | `MulMatQ4K.Gemm` 的 `tokens==1` 路由 | GEMV 服务单 token，GEMM 服务整批 |
| 3 | **共享激活量化** | `DecodeGateUp`/`MulMatPanel.QuantizeAndGemm` | 一次量化喂多个矩阵（q/k/v、gate/up） |
| 4 | **L2 列分块** | `GemmQ4K.ColTileBytes = 128*1024`、`MulMatQ2.ColTileBytes = 64*1024` | 权重切片驻留 L2、q8 行流式扫过 |
| 5 | **拓扑感知线程** | `CpuTopology.ChooseWorkerCount` + `CpuThreadPool.For`/`Barrier` | 物理 P-core 数 + job-id 轮询 + 自旋 barrier |
| 6 | **标量回退兜底** | `DotScalarForTest`/`DotScalar`/`Quantize4x8Scalar` | 无 AVX2 正确（慢），热路径总 SIMD |

六板斧像一层一层的"栈"：内存布局（斧 1）→ 计算形态（斧 2/3）→ 缓存利用（斧 4）→ 并行与基础（斧 5/6）。遇到新瓶颈，先从最底层斧子找起。

## 16.4 已知瓶颈与优化路线

把"已知慢、没修"的地方如实列出——是**路线图**，不是羞辱。

1. **MoE prefill**（`Qwen35Model.Moe.cs`）：逐专家 GEMV 各自独立量化、逐 token 串行。**怎么优化**：同一专家多 token 合并 panel GEMM。
2. **Gated-DeltaNet 递推**（`GatedDeltaNetOps.cs`）：每 token 分配 `float[]` + 三 pass 标量循环。**怎么优化**：就地 L2 归一化、向量化三 pass、分块复现——以 `GatedDeltaNetOpsTests` 为不破门槛。
3. **prefill 部分路径未插桩**：`Ticks*` 主要覆盖 decode。**怎么优化**：补插桩，没有"看见"就没有"改对"。
4. **Q5_K/IQ4_XS/STQ1_0 prefill**：无 panel GEMM。**怎么优化**：补 panel GEMM。
5. **softmax 的 FastExp 每元素分支**：`SoftmaxCausal` 里每元素一条分支。**怎么优化**：拆成无分支向量操作。
6. **KV 缓存是 f32**：decode 带宽受限。**怎么优化**：f16/i8 KV 缓存 + 量化/反量化内核。

这些路线图说明：**本书的"性能完结"是一块故意留下的画布**——"从零自制"的意义不在一份完美成品，而在让你自己继续优化的能力。现在你知道了六板斧、三件套探针、优化路线图的形状。剩下的，是你的路。

> **一句话总结这一章**：静态 `Ticks*`（`ProfileEnabled`/`ResetProfile`）做算子级剖面，`Q35_TRACE`/`Q35_DIAG` 定位流程与数值发散，性能设计六板斧构成优化决策框架，六条已知瓶颈是留给读者的优化路线图。引擎"能算、算对、且在通往更快的路上"——最后停下脚步，把边界与远方收进最后一块拼图。
